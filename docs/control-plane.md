# Control-plane audit and implementation plan

This is a source review of Headscale at commit `8106636c7f8d0cf8c9d4fb0beae94415069b768b`, the commit the project pins as v0.29.4. None of the conformance or capacity tests below has run.

Headscale is the control-plane foundation Covee builds on. Its stated goal is a narrow, single-tailnet server for personal use or a small organization ([declared scope](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/README.md#L37-L44)). It does not by itself provide every client, service, administrative workflow and operating guarantee of Tailscale's hosted product; Covee adds its own sign-in, console, gateway and deployment around it. This review records what the pinned Headscale implements, where its boundaries are, and what Covee must test.

## Runtime architecture

```text
Tailscale native client
  HTTPS /ts2021 -> Noise handshake -> per-connection HTTP/2 router
    /machine/register -> login/auth key/follow-up -> State -> NodeStore + DB
    /machine/map      -> machine/node binding check -> map session
                                                  -> State reconciliation
  policy/admin changes -> State -> policy compile -> peer adjacency rebuild
                                        -> mapper batcher -> map stream/deltas
  data path: client endpoints / direct encrypted tunnel / DERP relay
```

The graph is an architectural interpretation of the source links below. A compatible control plane sends identity, peer, policy, DNS, and routing configuration. It does not replace the native clients' tunnel engine, OS VPN integration, or all Tailscale-hosted services.

## Policy, revocation, DNS and routes

Policy compilation is a security boundary. The v2 policy manager compiles grants once, derives global and per-node filters, and chooses allow-all when both ACLs and grants are absent. A replacement must deliberately preserve or document that default; an empty policy and an explicit deny-all policy are different states. A write validates user references and evaluates ACL/SSH policy tests against a sandbox before replacing live policy. [Compilation/default](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/policy/v2/policy.go#L233-L262), [write validation](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/policy/v2/policy.go#L534-L582).

Peer visibility and packet permission are related but different outputs. Per-node packet filters are reduced to relevant rules, while peer relationships use reachability in both directions; a visible peer is not necessarily permission to initiate every kind of connection to it. Policy reload clears SSH check-auth cache, rebuilds peer adjacency, produces policy changes and selectively refreshes changed self capabilities. [Filter/visibility distinction](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/policy/v2/policy.go#L689-L774), [reload](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/state/state.go#L339-L387).

Revocation must remove stale client state, not merely stop issuing new permissions. Policy responses carry `PeersRemoved`, `PeersChanged`, replacement packet filters, SSH policy and DNS. The batcher explicitly handles the zero-visible-peers case because an empty `Peers` array does not necessarily clear the native client's prior peer list. Packet filters use a named `PacketFilters["base"]` replacement, including an empty filter. Patches are restricted to currently visible peers. These details deserve regression tests because one missed delta can preserve revoked access or metadata. [Policy delta](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/mapper/mapper.go#L320-L376), [zero-peer removal](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/mapper/batcher.go#L140-L164), [filter replacement](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/mapper/builder.go#L197-L216), [patch filtering](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/mapper/mapper.go#L454-L473).

For deletion, the map handler sends an expired self node to a reconnecting deleted client: native clients retry ordinary HTTP errors, while a past `KeyExpiry` drives the login state transition. Ephemeral logout deletes the node; normal logout and tagged-node behavior differ. Thus deletion, expiry, logout, and policy denial need separate acceptance cases. [Deleted-node response](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/noise.go#L725-L751), [logout semantics](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/auth.go#L205-L251).

DNS configuration is rendered into maps from server config, including resolvers and split-DNS routes; clients perform OS resolver integration. The documented feature set includes MagicDNS, global/restricted nameservers, search domains and extra records. Server policy updates also resend DNS to avoid stale resolver state. Verify client behavior for each supported OS; a map field alone does not prove OS DNS parity. Covee's isolated deployment acceptance (`python3 scripts/deploy.py check`) shows the pinned Linux userspace client receiving and applying global, fallback, split and search-domain settings and extra records from this coordinator; macOS and iOS remain open. [DNS generation](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/mapper/mapper.go#L133-L164), [declared DNS features](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/docs/about/features.md#L11-L15), [policy DNS reason](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/mapper/mapper.go#L320-L331).

Subnet routing uses announced ∩ approved routes plus policy and primary-router selection. This pin documents HA router health probes over Noise, with defaults of 10-second intervals and 5-second timeout; recovery does not immediately reclaim primary. This is **subnet-router failover**, not proof that multiple control servers can run active-active. DERP is a separate relay path, and the embedded server reuses Tailscale's DERP server library; configured client verification is fail-closed. [Route reconciliation](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/state/state.go#L3171-L3231), [HA config](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/config-example.yaml#L174-L192), [DERP construction](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/derp/server/derp_server.go#L52-L69).

## Persistence, concurrency and scale

`State` coordinates the database, IP allocation, policy, DERP map, bounded pending-auth cache and node cache. Its synchronization is process-local: `persistMu` prevents stale snapshots overwriting newer node state or resurrecting deleted nodes; registration locks serialize the same machine key. The source notes registration-lock entries are not pruned. [State fields and locks](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/state/state.go#L138-L208), [authoritative persistence](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/state/state.go#L524-L565).

NodeStore uses atomic copy-on-write snapshots with a write queue. Writes wait until committed; reads load the current snapshot. Snapshot generation can recompute peer adjacency over the node set. Mapper work is serialized per node, and an in-flight marker prevents later batches overtaking earlier ones. Each stream also needs backpressure and cancellation: channel sends time out, and session cancellation forces an HTTP write deadline. [NodeStore contract](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/state/node_store.go#L101-L122), [snapshot work](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/state/node_store.go#L672-L715), [ordered mapper work](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/mapper/node_conn.go#L63-L81), [send timeout](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/mapper/node_conn.go#L391-L421), [write cancellation](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/poll.go#L95-L107).

SQLite and PostgreSQL are implemented; SQLite uses one database connection, and upstream recommends SQLite while describing PostgreSQL as maintenance mode. A shared PostgreSQL database does not synchronize independent NodeStores, pending authentication, stream registries or peer-delta history. Treat multi-server coordination as unproven until explicitly designed and tested. [DB initialization](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/hscontrol/db/db.go#L964-L1025), [upstream DB guidance](https://github.com/juanfont/headscale/blob/8106636c7f8d0cf8c9d4fb0beae94415069b768b/docs/about/faq.md#L111-L118).

## Prioritized implementation workstreams

1. **P0: reproducible compatible baseline.** Keep exact server/client pins, provenance, licenses and a distinct project identity. Boot an isolated Headscale-based lab; enroll disposable clients through a custom login URL. Do not count packaging a foundation as writing an independent replacement.
2. **P0: authentication and revocation correctness.** Preserve machine/node-key binding, durable OIDC identity, expiry/logout differences, pre-auth-key semantics, full-first-map ordering, explicit peer removal and filter replacement. Complete the cases below before expanding surface area.
3. **P1: policy and operator experience.** Add a reviewed admin UI/API, roles, device approval, key lifecycle, audit history and policy preview with tests. Model owners/admins and OIDC group synchronization explicitly rather than spoofing capability bits.
4. **P1: self-owned connectivity and operations.** Operate DERP/STUN, DNS, subnet and exit routing with metrics, backups, restore drills and failure tests. Measure node/identity capacity and policy convergence. "No per-user or per-device limit" is a product promise; an infinite scale promise is not measurable.
5. **P2: missing hosted features.** Implement Services/VIP, Tailnet Lock, app connectors, HTTPS certificate/Serve/Funnel workflows and flow logs as separate specifications with observed inputs, state transitions and finite acceptance suites. Reuse open implementations where appropriate, recording inherited scope.
6. **P2: independent clients and distribution.** Separate common protocol/engine work from macOS/iOS/tvOS Network Extension, Windows service, Android VPN service, Linux and BSD packaging, updates and UI. Keeping official clients is a compatibility milestone, not independent native-client parity.
7. **P3: multi-server control-plane architecture.** Introduce a durable ordered event model, stream ownership, cache invalidation, registration coordination, node/route uniqueness constraints and split-brain behavior before claiming active-active operation. Use outage/restore evidence to choose the availability target.

## Production security follow-up

The original audit left main-branch leads #3517, #3526 and #3522 unreviewed. A follow-up compared their official diffs against the clean pinned `8106636c7f8d0cf8c9d4fb0beae94415069b768b` source. Release and main histories diverge; do not blindly switch to a different tag or assume that a merge on main is present in the release.

An additional source finding is independent of those PRs: `NoiseUpgradeHandler` accepts unregistered machine keys and mounts `/metrics` on the inner encrypted HTTP router (`hscontrol/noise.go:135-169`). A public proxy cannot inspect that inner path after the `/ts2021` upgrade. A private TCP 9090 listener therefore does not establish metrics isolation. Remove or authorize that inner route in a maintained reviewed patch and test access with an unregistered client. This surface is source-confirmed; its network behavior and disclosed metrics have not been demonstrated.

Headscale also mounts `/api/v1/*` on its main HTTP listener (`hscontrol/app.go:587-590`). Keep the backend unpublished and use a tested default-deny client-route allowlist or a reviewed listener split. TLS alone does not make this authenticated administrative API private.

The subsequent [downstream build](../deploy/headscale/README.md) applies pinned adaptations of the three upstream fixes and removes the inner metrics route, in a disposable copy of the locked upstream source. Its build runs a selected race-test suite in which 11 named regressions must pass: real never-enrolled Noise requests receive metrics 404, real clients clear SSH policy after withdrawal, and the replay, revalidation and logtail cases hold. Source/build hashes are recorded in its manifest. These findings and fixes are not an exhaustive security assessment or a production deployment. The [portable deployment contract](production-deployment.md) records remaining external identity, exposure and recovery gates.
